# Confidence calibrator card

- **Method:** Isotonic regression fitted by the pool-adjacent-violators algorithm with Beta(1,1) smoothing.
- **Artifact:** `models/confidence_calibrator.json`, generated by `experiments/evaluate_confidence.py`.
- **Input feature:** A heuristic evidence-support score using response status, verified tool/SQL evidence, query/evidence token overlap, and source count. It is not a model probability before calibration.
- **Labels:** The experiment runs the app over 18 authored synthetic scenarios and assigns correctness from explicit expected status, evidence-kind, and answer-fragment checks. Twelve cases fit the mapper and select an answer threshold; six fixed cases are held out.
- **Measured held-out results:** Brier score 0.2303 to 0.0359; expected calibration error 0.3720 to 0.1889; six of six cases were correct at the selected threshold. See `experiments/confidence_report.json` for case-level predictions and the exact threshold.
- **Intended use:** Demonstrate a reproducible calibration-and-threshold pipeline in this deterministic local synthetic application.
- **Not suitable for:** Estimating correctness on production traffic, making high-impact decisions, or establishing a safe deployment threshold. The six-case holdout is too small and shares a narrow synthetic corpus.
- **Retraining:** Replace `experiments/confidence_eval.jsonl` with a representative, independently reviewed, leakage-controlled dataset and rerun `python experiments/evaluate_confidence.py`. Reassess the threshold and coverage-risk tradeoff before release.
- **Known limitations:** Expected-outcome checks use a limited collection of answer substrings and evidence kinds. They do not verify claim-level entailment, semantic correctness, freshness, or citation support. Confidence must not be used as a substitute for those checks.
